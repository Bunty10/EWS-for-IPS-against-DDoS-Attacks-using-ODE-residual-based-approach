# Building "Residual-based ODE EWS IPS" (desktop app + installer)

Packages the whole project — Flask backend **and** the React GUI — into a
standalone Windows desktop application (its own window, **no console, no browser**)
and a Windows installer: **`Residual-based-ODE-EWS-IPS-Setup.exe`**.

## How it works

- The React app is built (`npm run build`) into `frontend/dist/`.
- `backend/dlt_app.py` serves that built GUI **and** the `/api/dlt` API from one
  Flask process — no separate web server or proxy.
- `backend/launch.py` is the app entrypoint. On launch it loads `.env`, auto-starts
  **live traffic capture** on a background thread, serves the API+GUI with
  **waitress**, and shows the GUI in a **native desktop window** (pywebview /
  Edge WebView2) opening on the **Dashboard**.
- **PyInstaller** (`ews.spec`) freezes everything into a **windowed one-folder** app
  `dist/Residual-based-ODE-EWS-IPS/Residual-based-ODE-EWS-IPS.exe`
  (`console=False` hides the CMD window; `uac_admin=True` requests admin so packet
  capture works). The app icon is `packaging/icon.ico` (generated by
  `packaging/make_icon.py`).
- **Inno Setup** (`installer/ews.iss`) wraps that folder into
  `installer_output/Residual-based-ODE-EWS-IPS-Setup.exe` with Start-menu/desktop
  shortcuts and the app icon.
- Runtime data (SQLite alert DB, uploads, results, and an optional `.env`) lives in
  **`%LOCALAPPDATA%\Residual-based-ODE-EWS-IPS\`** (never in Program Files).

## ⚠️ Build on Windows

PyInstaller builds for the OS it runs on (no cross-compile) and Inno Setup is
Windows-only. Build on **Windows** to get the `.exe`/installer.

## Prerequisites (Windows build machine)

- **Python 3.10+** and **Node.js 18+** on `PATH`
- **Inno Setup** (installer step): https://jrsoftware.org/isdl.php or `choco install innosetup`
- **Npcap** (https://npcap.com) — required at *runtime* for live packet capture
- **Edge WebView2 Runtime** — preinstalled on current Win10/11 (older images: install the free Evergreen runtime)
- ~2–3 GB free disk for the build (numpy/pandas/scikit-learn/scapy bundle)

## Build

```bat
build.bat
```

Steps it runs: build frontend → install deps → generate icon + PyInstaller →
Inno Setup. Results:

- **Desktop app:** `dist\Residual-based-ODE-EWS-IPS\Residual-based-ODE-EWS-IPS.exe`
- **Installer:** `installer_output\Residual-based-ODE-EWS-IPS-Setup.exe`

(If `ISCC` isn't installed, the build stops after PyInstaller and points you at the
ready-to-run app folder.)

## Run

1. Run **`Residual-based-ODE-EWS-IPS-Setup.exe`** → installs + adds shortcuts.
2. Launch **Residual-based ODE EWS IPS** from the Start menu / desktop and accept the
   **UAC prompt** (needed for packet capture). A native window opens on the
   **Dashboard**; live capture starts automatically.
3. To enable email, create `.env` in the install folder or in
   `%LOCALAPPDATA%\Residual-based-ODE-EWS-IPS\` (template: `backend\.env.example`):
   ```
   SMTP_HOST=smtp.gmail.com
   SMTP_PORT=587
   SMTP_USER=you@gmail.com
   SMTP_PASS=your-app-password
   ALERT_EMAIL_TO=admin@example.com
   ```
   Then in **Admin → Email notifications**, turn the toggle **ON** and click
   **Send test**.

## Versioning & installing multiple versions side by side

Each install's identity is its **AppId** in `installer/ews.iss`. You can use any
unique string (a GUID is common but not required). Two installers with the **same
AppId** are the same app — a newer one upgrades/replaces the older; **different
AppIds** install as separate apps that coexist.

The installer is parameterized by version, so you don't edit the script per release:

```bat
REM Side-by-side (default): v1.1.0 installs ALONGSIDE any other version
ISCC /DAppVersion=1.1.0 installer\ews.iss

REM Upgrade-in-place: a new build replaces the previous install
ISCC /DAppVersion=1.1.0 /DSideBySide=0 installer\ews.iss
```

In side-by-side mode (`SideBySide=1`, the default) the version is folded into the
AppId, the install folder (`Residual-based-ODE-EWS-IPS-<version>`), the Start-menu group and
the setup file name — and each installed version keeps its **own data folder** under
`%LOCALAPPDATA%\Residual-based-ODE-EWS-IPS-<version>\` (so alerts/results don't mix). `build.bat`
builds with the version currently set in `ews.iss` (`#define AppVersion`); bump that or
pass `/DAppVersion=` to produce a new coexisting version.

## Live capture on client machines (Npcap) — required

Live capture uses scapy, which needs the **Npcap** driver on the machine that runs
the app. This is the usual reason live traffic "works in dev but not on another
PC": the dev machine has Npcap, the client doesn't. The build now bundles and
installs Npcap for you:

1. Download the Npcap installer from https://npcap.com.
2. Save it as **`installer/vendor/npcap-installer.exe`** (exact name).
3. Build with `build.bat`. `installer/ews.iss` copies it into a temp folder and
   runs it during setup **only when Npcap isn't already installed** (checked via
   `wpcap.dll`), enabling WinPcap API-compatible mode and loopback support.

If the file is missing, `build.bat` prints a warning and the setup still builds —
but clients without Npcap won't be able to run live capture. Npcap's license does
not permit fully silent redistribution, so its installer runs interactively.

The app already requests **admin** at runtime (`uac_admin=True`) and the installer
runs elevated, both required for packet capture. When capture still can't start,
the Admin panel and the live views surface a clear, actionable Npcap message
(see `dlt/live_capture.py`) instead of a cryptic error.

## Where result CSVs are stored

Live Traffic and Uploaded-CSV results (and the SQLite alert DB) are written to a
**writable per-user folder** — never inside Program Files, which isn't writable:

| Build | Results folder |
|-------|----------------|
| Development (`python dlt_app.py`) | `backend/dlt_results/` |
| Installed `.exe` | `%LOCALAPPDATA%\Residual-based-ODE-EWS-IPS\dlt_results\` |
| Custom | `<EWS_DATA_DIR>\dlt_results\` when the `EWS_DATA_DIR` env var is set |

Clients don't have to hunt for it: the **Admin panel → "Data storage location"**
card shows the exact folder and lists the stored CSV files, and
`GET /api/dlt/admin/storage` returns the same info as JSON. Each stored CSV now
contains the **complete** per-second data — timestamp, socket features
(IP/port/protocol) and all time-based flow features together.

## Troubleshooting

- **Blank window** → Edge WebView2 Runtime missing (pywebview falls back to browser).
- **No packets** → install Npcap and accept the UAC prompt (app runs as admin).
- **SMTP fails only in the build** → fixed via the bundled `certifi` CA bundle
  (`dlt/notifier._ssl_context`); ensure `SMTP_*` are set and the toggle is ON.
- **Antivirus/SmartScreen** may flag an unsigned build — code-sign, or *More info → Run anyway*.
- **Slimmer build** → the residual ML core is NumPy-only; there is no PyTorch wheel to bundle.
